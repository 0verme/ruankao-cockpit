# 数据流风格：批处理与管道过滤器

## 今天学会什么
- 区分完整数据批次与持续数据流的处理方式。
- 描述管道、过滤器及其松耦合关系。
- 根据实时性、顺序与并行需求辨认两种结构的取舍。

## 先建立直觉

两种风格都把系统看成一串数据处理步骤，但数据交接的粒度不同：批处理等一整批数据完成后再交给下一步；管道过滤器允许一部分数据先流向后续步骤。

## 核心知识

### 批处理
系统由相对独立的步骤组成，数据以完整、有限的批为单位顺序流过各步骤。前一步完成并交出完整结果后，下一步才开始。来源列出的特征是实时性低、数据整体处理、步骤严格顺序、每一步可作为独立程序。由此可见，处理边界清楚，但不能把它当作边到达边处理的流式链路。

### 管道-过滤器
系统被拆为独立过滤器，每个过滤器执行特定数据变换；管道连接上游输出和下游输入。过滤器从管道取数据并将结果写回，彼此不共享状态，只需遵守输入输出数据格式。数据可按记录或数据块流动，不必等完整数据集到齐；过滤器相互独立也允许在数据准备好时并行运行。

来源将管道过滤器描述为实时性较高；具体部署场景未给出，本单元不把它扩展为所有流处理系统的性能保证。

## 一张脑图式结构
```text
输入数据
├─ 批处理：完整批 → 步骤1完成 → 步骤2开始 → …
└─ 管道过滤器：数据块/记录 → 过滤器A → 管道 → 过滤器B
                 （不共享状态，只约定输入/输出格式）
```

## 易混点 / 对比
| 维度 | 批处理 | 管道-过滤器 |
|---|---|---|
| 交接粒度 | 完整批次 | 流或数据块 |
| 下游启动 | 上游全部完成后 | 数据就绪即可处理 |
| 来源强调 | 顺序、整体、实时性低 | 松耦合、可并行、实时性较高 |

## 架构师视角
若需求要求完整批次一致处理且步骤边界清晰，批处理结构容易表达；若希望数据逐步流动并让独立步骤并行，则需要管道式组织，同时明确各步的数据格式。选择依据应来自数据到达方式和处理目标，而非仅凭“数据量大”。

## 记忆锚点
- 批处理等整批；管道过滤器可逐块流动。
- 过滤器封装变换，管道连接输入输出。
- 独立、无共享状态是来源强调的解耦条件。
- 本项只覆盖数据流风格中的两个子类。
