# 性能设计战术：资源、异步与批处理

## 今天学会什么
- 概括资源隔离、异步、内存计算、预计算、批处理五种来源列出的性能战术。
- 识别每种战术减少的主要开销或争用。
- 说明其代价或前提不能被“性能提升”一词掩盖。

## 先建立直觉

性能战术通过减少等待、重复计算、交互次数或资源争用来改善系统表现，但每种方法针对的瓶颈不同。先找到耗时来自哪里，再选择战术，比把所有优化都叫作“加缓存”更可解释。

## 核心知识
- **资源隔离：**用物理或逻辑边界划分共享资源，减少资源争用与相互干扰，也有助阻断故障传播。
- **异步：**请求发起后不必等待耗时操作完成；后台继续执行，再通过回调、事件或消息通知结果。来源列出多线程和消息中间件作为实现方式；收益包括降低响应延迟、提高吞吐、解耦和削峰填谷。
- **内存计算：**把数据放在内存中计算，以避免磁盘 I/O 和网络传输带来的延迟。
- **预计算：**提前执行复杂计算并持久化结果，请求到来时读取现成结果，是“以空间换时间”的策略。
- **批量处理：**把多个细粒度操作合并成较粗粒度的一次处理，以减少交互次数和系统调用开销、提高整体吞吐。

## 一张脑图式结构
```text
性能瓶颈 → 对应战术
├─ 资源争用 → 隔离
├─ 请求等待 → 异步
├─ I/O / 网络传输 → 内存计算
├─ 重复的昂贵计算 → 预计算（空间换时间）
└─ 高频小操作交互开销 → 批量处理
```

## 易混点 / 对比
- 异步强调调用方不必同步等待；它不等同于“多线程”这个实现方式。
- 内存计算与预计算不同：前者减少数据访问延迟，后者提前计算并保存结果。
- 批处理通过合并操作减少交互；不能在不检查业务语义时任意合并。

## 架构师视角
每种战术把成本从一个位置移到另一个位置：预计算占用存储并需要处理结果更新；异步降低等待但要管理结果通知；隔离减少干扰但会改变资源分配。架构决策应说明目标瓶颈与接受的代价，而不是只写“提高性能”。
