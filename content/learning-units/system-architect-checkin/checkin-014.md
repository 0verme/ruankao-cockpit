# 仓库与黑板架构

## 今天学会什么
- 说明仓库风格中组件如何围绕中央数据存储交互。
- 说明黑板风格由黑板、知识源和控制机制组成。
- 根据数据状态是“记录”还是“动态求解状态”区分两者。

## 先建立直觉

两种风格都让组件通过共享数据协作，但共享数据承担的角色不同：仓库通常保存系统核心数据；黑板则承载问题求解过程中不断变化的中间状态，知识源依据状态贡献下一步信息。

## 核心知识

### 仓库风格
中央数据库或数据仓库存放核心数据，多个相对独立的功能组件通过它交互，而不是彼此直接通信。仓库集中维护数据完整性、一致性和持久化；组件可各自关注业务逻辑。来源指出，组件之间少直接依赖有利于独立修改、替换或增加。

### 黑板风格
问题没有预先固定的求解路径。黑板存放初始数据、中间状态和最终解；知识源封装某一部分领域知识，只有需要的数据状态出现时才可能被激活；控制机制根据当前黑板状态决定接下来运行哪个知识源。解在知识源持续观察与贡献中逐步演化。

## 一张脑图式结构
```text
共享数据中心
├─ 仓库：核心数据/记录
│  └─ 独立组件通过中央存储交互
└─ 黑板：动态求解状态
   ├─ 黑板存状态
   ├─ 知识源贡献局部知识
   └─ 控制机制选择下一知识源
```

## 易混点 / 对比
| 维度 | 仓库 | 黑板 |
|---|---|---|
| 数据角色 | 相对静态的记录 | 随推理/求解动态演化的状态 |
| 组件协作 | 围绕中央数据存储 | 知识源由当前状态触发并贡献 |
| 关键结构 | 仓库与独立组件 | 黑板、知识源、控制机制 |

## 架构师视角
若组件共享的是持久业务数据，仓库式中心化可以减少彼此直接依赖，但集中式数据边界需要被明确管理；若问题求解路径依赖不断形成的中间状态，黑板风格强调状态和调度机制。题目场景应先识别共享数据的语义，再选择结构。
