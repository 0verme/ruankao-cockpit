# 区块链：账本、共识与分层

## 今天学会什么
- 概括区块链的链式账本与多方维护特征
- 区分公有链、私有链、联盟链的参与与治理边界
- 识别数据、网络、共识、激励、合约、应用六层职责

## 先建立直觉

区块链把状态记录组织成按序相连的区块，由多个网络参与者按共识规则校验和维护。其核心问题不是“用了哈希就绝对不可改”，而是参与者如何在没有单一中心控制的情况下接受状态更新。

## 核心知识

### 基本属性与类型

来源列出去中心化、多方维护、哈希链及共识校验等特征。公有链面向开放参与；私有链由单一组织控制写入；联盟链由多个获准机构共同维护。三者的参与权限、效率和信任假设不同。

### 智能合约与分层

智能合约是部署在链上的程序，在条件满足时执行预设动作。六层由下而上为数据（区块结构、链式连接与完整性）、网络（节点连接和数据传播）、共识（决定写入状态）、激励（促进参与并约束行为）、合约（业务逻辑）、应用（面向用户的场景服务）。

**SOURCE_GAP：区块链类型、共识安全边界与智能合约执行约束未由仓库独立来源核验；避免把来源中的绝对化表述写成保证。**

## 一张脑图式结构

```text
数据 → 网络 → 共识 → 激励 → 合约 → 应用
参与治理：公有（开放） / 私有（单组织） / 联盟（授权成员）
状态更新依赖规则、节点校验和共识
```

## 易混点 / 对比

公有/私有/联盟链主要按参与与治理权限区分；六层架构按系统职责划分。去中心化程度、效率和隐私约束之间存在取舍，不能简单说某一类型全面更安全。

## 架构师视角

只有在多方需要共同维护状态、且治理和验证规则可接受时，分布式账本才值得评估。公开透明、共识成本、隐私、吞吐和参与权限需要一起考虑；来源提及的农产品溯源只是案例标签，没有足够材料推断方案效果。
