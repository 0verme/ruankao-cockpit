# RUP：迭代、阶段与工作流

## 今天学会什么

- 说出 RUP 的三项特征：迭代与增量、用例驱动、以架构为中心。
- 按目标区分初始、细化、构建、移交四个阶段。
- 说明“阶段”和“核心工作流”不是同一组分类。

## 先建立直觉

RUP 把软件开发组织成迭代推进的过程：用例帮助贯穿需求到测试，架构为开发提供中心结构；阶段则按项目逐步成熟的目标划分。可以把阶段想成“当前要把项目推进到什么状态”，把工作流想成“要持续做哪些种类的工作”。

## 核心知识

### 三项特征

- **迭代与增量：**各阶段中通过迭代推进，并形成可工作的软件增量。
- **用例驱动：**用例贯穿需求、设计、实现和测试。
- **以架构为中心：**开发活动围绕架构展开。

### 四个阶段看阶段目标

| 阶段 | 主要目标 | 来源列出的代表工作 |
|---|---|---|
| 初始 | 建立业务模型、界定项目边界 | 估计项目规模与风险、计划、技术评审 |
| 细化 | 分析问题领域、建立架构、处理最高风险 | 确定架构、制定构建计划、建立支持环境、选择构件、评审 |
| 构建 | 开发并集成构件，形成产品 | 开发、集成、测试、评审 |
| 移交 | 使软件对最终用户可用 | β 测试、发布、用户文档、培训、收集反馈和调整 |

### 九个核心工作流看活动类型

业务建模用于理解组织及业务；需求定义功能与界面；分析与设计把需求转成模型；实现把设计模型变成可执行实现并集成；测试检查交互、需求实现和质量缺陷；部署负责打包、分发、安装、升级与支持；配置与变更管理维护制品完整性和一致性；项目管理提供计划、人员、执行监控和风险管理框架；环境提供过程与工具支持。

工作流不是四阶段的同义词。RUP 在不同阶段中安排这些工作流，具体投入随阶段目标变化；来源提纲没有给出定量比例，本单元不自行补充。

## 一张脑图式结构

```text
RUP
├─ 特征：迭代增量 / 用例驱动 / 架构中心
├─ 阶段（项目目标）
│  ├─ 初始：边界与业务
│  ├─ 细化：架构与主要风险
│  ├─ 构建：实现、集成、测试
│  └─ 移交：发布、培训、反馈
└─ 工作流（工作类型）
   ├─ 业务建模、需求、分析设计、实现、测试、部署
   └─ 配置变更、项目管理、环境
```

## 易混点 / 对比

- **四阶段**描述项目推进的目标；**九个工作流**描述开发活动的类型。
- “以架构为中心”不是只在细化阶段画架构；来源将它列为 RUP 的整体特征。
- 初始阶段的重点是边界与可行计划；细化阶段明确包括建立架构并淘汰最高风险因素。

## 架构师视角

RUP 将架构放在过程中心，并要求在细化阶段建立架构、处理主要风险。架构师需要让架构决策尽早回应高风险问题，同时让用例、设计、实现和测试保持可追踪关系。阶段和工作流分开表达，能避免把项目进度阶段误当作团队职责列表。
