# 敏捷开发：宣言与常见方法

## 今天学会什么

- 复述敏捷宣言中的四组价值取向，并理解它们是取舍而非“右侧完全不要”。
- 区分 XP、Scrum、DSDM、Crystal、FDD、TDD 与精益在原提纲中强调的对象。
- 用迭代、反馈和协作解释敏捷方法与过程管理的关系。

## 先建立直觉

敏捷不是“不要计划、不要文档”，而是在交付过程中更重视人与协作、可工作的增量、客户合作和响应变化。计划与文档仍可能需要，只是不把它们置于可用软件、反馈和变化响应之上。

## 核心知识

### 宣言与整体特征

四组价值取向是：个人和交互胜过过程和工具；可工作的软件胜过大量文档；客户合作胜过合同谈判；响应变化胜过遵循计划。原提纲将敏捷概括为以人为核心、迭代、循序渐进，并列出短会、小版本、客户参与、自动化测试、适应性计划、结对编程等做法；管理侧关注测试驱动开发、持续集成和重构。

### 以方法的“主抓手”区分

- **XP（极限编程）：**价值观为沟通、简单、反馈、勇气；提纲列出的原则包括快速反馈、简单性假设、逐步修改、提倡更改、优质工作。
- **Scrum：**角色是产品负责人、敏捷教练、开发团队；活动围绕 Sprint 规划、每日站会、评审、回顾和 Sprint；工件为产品待办列表、Sprint 待办列表、增量。
- **DSDM：**以业务为核心，追求快速、有效的系统开发。
- **Crystal：**按项目规模调整流程，强调沟通与交付。
- **FDD（特征驱动开发）：**以功能特征为单位，关注领域建模与迭代设计；五个核心过程是整体对象模型、特征列表、计划特征开发、特征设计、特征构建。原提纲还列出项目经理、首席架构设计师、开发经理、主程序员、程序员、领域专家六类角色。
- **TDD（测试驱动开发）：**先写测试，再小步实现并重构，以自动化测试支撑设计与实现。
- **精益软件开发：**强调消除浪费、增强学习、延迟决策。

## 一张脑图式结构

```text
敏捷开发
├─ 价值取向：协作 / 可工作增量 / 客户合作 / 响应变化
├─ 迭代与反馈
│  ├─ XP：反馈、简单、逐步修改
│  ├─ Scrum：Sprint + 角色 + 工件
│  ├─ FDD：以特征组织工作
│  └─ TDD：测试先行、自动化、小步重构
└─ 其他侧重点
   ├─ DSDM：业务驱动
   ├─ Crystal：按规模调流程、重沟通交付
   └─ Lean：消除浪费、学习、延迟决策
```

## 易混点 / 对比

- **XP 与 Scrum：**原提纲对 XP 给出价值观和原则，对 Scrum 给出角色、活动与工件；不要把 Scrum 的工件名称当作 XP 的价值观。
- **TDD 与“测试是最后阶段”：**TDD 把测试用于驱动开发活动，不只是交付后的检查。
- **FDD 与一般的功能列表：**提纲还强调领域建模及计划、设计、构建等按特征推进的过程。

## 架构师视角

敏捷环境中的架构工作需要与可工作的增量和变化反馈并行。架构师要能解释哪些设计决策可以随迭代调整，哪些接口或约束需要团队共同遵守；“响应变化”不等于取消架构沟通。来源没有规定通用的架构文档数量或流程模板，因此不在此扩展。

## 记忆锚点

- 敏捷宣言是四组“更重视什么”的价值取向，不是右侧事项一律禁止。
- Scrum 记角色、活动、工件；XP 记价值观与原则。
- FDD 以特征组织开发，TDD 以测试驱动实现。
- DSDM 看业务，Crystal 看规模适配与沟通交付，Lean 看浪费与学习。
